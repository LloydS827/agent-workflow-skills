### 2026-11-07 初始化技能的父页选择

从 `34b2c26` 的初始版本和本轮修订版分别安装技能。两个独立 Agent 显式调用各自的 `init-notion-project`，使用相同的六组请求、项目 README 和模拟 Notion 页面。检查答复及页面数据前后差异：

| 输入 | 观察结果 |
| --- | --- |
| 用户给的父页与项目约定不同 | 两版都用了用户给的父页。 |
| 仅项目 README 约定了父页 | 两版都在约定的父页下建立主页。 |
| 两者都缺失，工作区中有「项目总览」 | 旧版在「项目总览」建页。新版给出草案，询问父页链接，写入次数为零。 |
| 直接给出四区齐备的已有主页 | 两版都返回原页，保留人工排列、文档和已有数据库视图。 |
| 上次操作超时，主页已存在 | 两版都定位到原主页，只补缺少的里程碑占位。 |
| 项目约定的名称匹配两个父页 | 两版都列出候选，请用户选择。 |

项目检查、YAML 解析及临时项目的安装校验均通过。Skill Creator 的通用检查器对两版均报告 `disable-model-invocation` 超出其字段清单，本库保留该字段以维持跨工具的显式调用。此次行为验证使用模拟数据，真实 Notion 写入和界面验收待试用项目验证。

### 2026-11-10 父页上的项目条目

只读查看团队的项目总览及两个项目主页后，用四组虚构数据对照修订前后的安装副本。两版在有阶段和简介的总览中都复用了新子页入口，填写本项目已有依据的内容。区别出现在只列名称、链接和人工备注的目录里：旧版额外加了简介，新版沿用现有字段和原条目。另两例分别复用了业务 README 登记的主页、在缺少位置约定时询问父页。写入结果均来自模拟页面。

### 2026-11-10 初始化技能的 MCP 前提与指令语言

用两个独立会话显式调用 `init-notion-project`，分别使用中文入口和等义的英文入口。两边使用同一组中文请求、相同的共享参考、模拟权限和初始页面。每个入口各跑一轮，核对操作记录、最终页面及答复。

八个场景均达到预期。只要草案时直接交付，已有主页按区域用途判重，用户指定的父页优先，缺少位置约定时询问父页，中断后只补缺项。其余三例专门检查 MCP：没有工具时交付未写入的草案，只有读取权限时定位父页并说明缺少创建权限，工具齐备时按唯一名称找到父页并建立主页。两版在这些决定上一致，正文详略和读取次数略有差别。本次未比较延迟、费用或其他模型。

另在已授权的真实工作区按名称搜索并读回了父页。新建、更新和中断恢复使用模拟页面验证。

发布复验时，在空项目安装全部 24 项技能，逐文件校验 74 个文件一致，本机 Codex 从该项目发现全部 24 项。使用安装副本按名称定位父页，再读回一个已有项目主页，确认原任务库、里程碑库、项目文档和进展记录已涵盖四区，写入次数为零。
