# Project Docs

将方案与证据转为正式交付材料，使读者能够理解方案、评估依据并作出所需决定。

## 1. 明确交付与依据

读取用户材料、方案、原始结果和现有版本，区分事实来源与风格模板。确定读者、用途、必要内容、格式和篇幅，沿用交付目录并告知路径。已有决定直接采用，仅对影响内容或承诺的缺口集中提问。

关键结论回溯原始证据；预算核对数量、单价、单位及估算依据。资料冲突按证据和已确认决定解决。需要补充外部证据时调用 `research`：有技能调用工具时用工具加载，否则读取其 SKILL.md 并执行。

## 2. 组织内容

优先遵循用户指定结构；决策材料通常按结论、依据和实施条件展开。项目方案交代对象、需求、采用路线与投入；结果报告保留方法、条件、结果和适用范围；汇报聚焦本次决定；预算呈现输入、计算关系和估算口径。

成熟内容直接制作；结构存在实质取舍时先给可审阅提纲与问题，继续完成不依赖回答的部分。

## 3. 写作与制作

使用连贯、自然的正式文字，正面描述方案；表格用于比较或数据，列表用于步骤或并列项。删除过程话术、重复摘要和装饰性信息。

区分目标、估算与实测结果；必要的不确定性作为正式条件保留。技术主张注明对象、条件、方法、证据及适用范围。现场照片使用原始材料，示意图明确标识。

仅制作请求的格式。调用相应文件技能：Word 用 `documents`，演示文稿用 `presentations`，工作簿用 `spreadsheets`，PDF 用 `pdf`；无技能调用工具时读取对应 SKILL.md 并执行。沿用用户模板，需要继续编辑的图表和数据保留可编辑性。

多份材料共用同一套事实，数字、条件或结论变更时同步受影响的交付物。原材料和内部处理记录与正式成果分开保存。

## 4. 检查与交付

按 [交付检查](references/delivery-check.md) 完成内容和最终呈现两轮检查。排版文件实际渲染；预算以公式计算并重算核验。检查发现问题后修订并复查受影响部分。

返回文件路径或目标文档链接、影响使用的未决事项与未执行的检查。生成成功不等于检查通过。制作材料不自动授权发送、发布或修改分享范围；语雀由项目经理维护。
