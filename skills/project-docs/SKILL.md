# 制作正式项目材料

把项目事实写成读者拿到就能使用的文件。对外材料应当自足：理解对象、范围、结论、依据与限制所需的信息，都在交付物内。多份文件采用同一套数字和条件，可能单独流转的每份文件均须能独立阅读。

## 执行流程

1. **明确读者与依据。** 确认读者要作什么决定、所需格式和交付位置。区分事实来源、内部讨论、样式模板和可对外交付的材料。取舍按原始证据和已确认的变更。确需外部补证时调用 [research](../research/SKILL.md)。需要借鉴同类报告时只参考其结构和呈现，项目数据仍取自本项目。
2. **组织论证。** 范围仍在讨论时先起草可审阅的提纲或 Markdown，集中处理影响承诺的取舍；内容成熟就制作指定格式。优先遵循用户模板。方案讲清对象、场景、工作方式及分期投入；报告说明条件、方法、结果和适用范围；汇报围绕本次决定；预算说明计量单位、数量、单价和估算依据。未知项写明什么证据或阶段能使估算收敛。
3. **转换为读者的语言。** 对外使用完整的对象或方法名称。必须反复使用的专业缩写，在首次出现处写全称并解释用途；通用单位和目标读者熟悉的术语可直接用。将内部代号、工单号、批次简称、内部材料名及私人链接换成可披露的事实、方法和条件。来源无法解释或不宜公开时，保留可支持的结论范围，将需补证的主张移出正式结论，内部核查线索另存。
4. **制作并验收。** 按下表调用当前可用的格式技能。没有调用工具时读取已安装的技能说明，或用能完成同等制作与检查的工具。保留需要编辑的数据和图表。数量、条件、结论发生变化时同步所有受影响文件。按[交付检查](references/delivery-check.md)做外部读者检查、内容核对和最终渲染，修订后复查。交付实际文件及影响使用的未决事项。发布和分享按授权处理，团队的语雀发布由项目经理维护。

## 按格式选择制作能力

| 格式 | 制作与检查 |
| --- | --- |
| Word 或 PDF | 用文档或 PDF 能力（如 `documents`、`pdf`）生成正文，逐页查看最终文件中的分页、图表、页眉页脚及链接。 |
| 演示文稿 | 用演示能力（如 `presentations`）逐页制作和查看。采用 HTML 截图制作时保留内部可复查源稿，需编辑的图表保持可编辑。 |
| 工作簿 | 用表格能力（如 `spreadsheets`）保留输入与公式，试改数量以验证重算。核对正式输入、总额、每张表及打印区域。 |
| Markdown | 直接核对正文、证据与链接，按用户要求交付。 |

例如，内部写「按 QA-17 已通过，详见项目群」。面向客户时，若披露范围允许，可写「在额定压力下对密封组件连续测试 2 小时，未观察到渗漏。现场长期表现仍待验证」。只有原始材料支持的条件和数字才能写入。
