# 检查与交付

在修订现有文件、准备发布或交付前使用。

## 修订的基准

开始修改时读取用户指定文件的当前内容。可记录修改时间或摘要值，在替换文件前再核对，以识别工作期间发生的手动更改。若出现新改动，重新读取并合并到当前版本。

把修改要求对应到页面和对象。局部修订完成后，检查前后页衔接、目录、交叉引用与总页码。用户要求修改现有文件时，验证成功后写回约定位置。

## 四项检查

| 检查方面 | 直接证据 |
| --- | --- |
| 要求与内容 | 每项明确要求都能在指定页面或交付物中找到，名称、数值、范围和状态相符 |
| 表达与逻辑 | 标题受正文支持，层级和术语一致，例子服务于论点，愿景与现状表达清楚 |
| 视觉与格式 | 实际渲染无意外重叠、裁切、缺字或不可读文字，图片和图表完整 |
| 交付与编辑 | 最终文件可打开，页序正确，所需文本、表格和图表仍可编辑，图片已嵌入 |

整套新稿查看每页。局部修改详细检查受影响页，并浏览整套以发现连带变化。缩略图适合检查整体节奏，实际尺寸用于检查细节。

导出格式与在线预览可能不同。交付 PPTX 时检查实际导出的文件。若出现中文缺字，先检查渲染环境的字体和替代规则，再判断文件内容是否有问题。对使用某个应用检查过的表述，以实际操作为准。

## 可选的 PPTX 盘点工具

使用 Python 标准库运行技能目录中的脚本。

```bash
python3 scripts/inspect_pptx.py "/path/to/deck.pptx"
python3 scripts/inspect_pptx.py "/path/to/deck.pptx" --terms "/path/to/required-terms.json" --slide 6
```

默认输出真实演示顺序、每页对象内的原生文字和表格／图片／图表数量。第二种方式检查指定页是否包含清单中的名称或其认可别名。省略 `--slide` 时检查整套可见页面。备注、图片文字、图表内部文字和母版继承文字不计入覆盖。

词项清单格式如下。别名应由用户资料或明确的等价关系支持。

```json
[
  {"name": "需要完整出现的名称"},
  {"name": "另一个名称", "aliases": ["已认可的简称"]}
]
```

脚本逐项匹配字面名称，统一 Unicode 形式和空白。输出 `matched` 与 `missing`，缺项时返回状态码 1，读取错误时返回 2。它不能判断别名是否合理、图中文字是否真实可见、论证是否完整或版式是否美观。

## 来源、命名与完成

根据受众和用户要求呈现来源。对外资料优先保留公开可访问的来源。内部资料可作为编写依据，其引用方式按用户明确要求处理。长链接可放在备注或文末 Reference，避免干扰正文。数字与研究主张保留足以核查的出处。

本地文件遵循约定的 `YYMMDD-` 命名和版本方式。新增版本应同步文件名、封面、页码及相关元信息。保持成果名称与用户现有管理习惯一致。

只有内容、视觉、可编辑性和交付位置均核对完成，才声明完成。报告仍影响使用的限制。将用户需要的最终文件或在线文档提供为可访问链接。
