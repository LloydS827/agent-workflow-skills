# To Notion

综合已有讨论与证据，形成可用于下一步工作的内部方案。**Notion 原生正文是方案源**，实现和实验记录保留在原位置，用链接引用。

## 1. 读取依据与目标页面

需要读取或写入 Notion 时，先按[Notion MCP 检查](../_shared/record-writing.md#notion)核实当前会话的工具和目标页访问权。

读取讨论、现有方案和相关证据；软件任务检查相关实现、测试、领域术语和 ADR，研究与系统任务检查已有结果及验证条件。

读取 [记录写入](../_shared/record-writing.md) 的通用规则与 Notion 部分，定位并告知保存页面。位置未定时继续整理草案。项目已有主页时读取 [Notion 项目布局](../_shared/notion-project.md)，优先沿用现有分类与原文档；新增常用文档在主页分类直达正文，不建立空目录。

## 2. 综合方案

沿用已确认的决定，直接综合。只有影响目标、路线或验收的缺口才集中询问；待验证的假设明确保留，不重启完整访谈。

按用途选择内容：

| 用途 | 正文必须说清什么 |
| --- | --- |
| 需求或建设方案 | 用户的问题、采用方案、范围与排除项、可观察行为和完成条件 |
| 研究规划 | 问题、已有依据与候选解释、比较基线、条件、所需证据与判断方式 |
| 技术决策 | 候选方案、选择依据、适用条件及重审条件 |
| 结果或里程碑 | 实际成果、证据、适用范围及剩余差距 |

软件方案覆盖本轮所有用户场景、关键失败行为、必要的接口或数据约定。测试优先选用已有、较高层且尽量少的接口，验证外部行为；记录测试先例。沿用已认可的测试边界，新增或改变边界时请用户确认。

正文写决定与依据，避免易过期的文件清单和实现代码；原型中比文字更精确的状态机、类型或结构可保留必要片段。重要主张就近引用来源，区分目标、建议与实测结论。

## 3. 保存与交付

按写入参考更新指定页面；草案请求只交付草案，本地导出按需提供并标注来源。涉及执行安排的变化指出受影响工作，任务与数据库调整由 toPM 按对应授权处理，本入口不自动启动执行拆解。

完成时，本轮范围和完成条件均已表达，关键未知项可见，已保存内容经过回读。返回目标页面名称与链接、主要变化及未完成事项；草案明确尚未写入 Notion。
