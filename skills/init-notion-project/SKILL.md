# 初始化 Notion 项目主页

需求澄清后，建立或补齐团队共用的 Notion 项目主页，汇集已有材料，供后续用 `to-notion` 编写方案。交付物是可直接打开的主页链接。用户只要草案时，直接按[主页样例](#主页结构与样例)交付正文，注明尚未写入。

实际初始化需要当前 Agent 已接入并授权 **Notion MCP**，可通过官方插件提供。

## 执行流程

### 1. 定位项目

先按[Notion MCP 检查](../_shared/record-writing.md#notion)发现可用工具。优先定位用户指定的主页或父页，其次查业务项目的 README、项目指引或其引用的团队约定。按名称搜索，已有引用则直接读取。有本项目的主页就复用，新建时采用约定的父页。仍无位置时，询问应放在哪个父页，并先准备草案。

在父页下定位时，先读父页已有内容，用项目名称、已有标识和条目链接核实主页。同名候选仍无法区分时，列出位置请用户指明。目标页无法访问时，说明需要哪个页面的访问权限。

### 2. 建立或补齐主页

写入前按[记录写入约定](../_shared/record-writing.md#通用规则)告知目标位置和本次操作。

- **新主页**按文末的[主页结构与样例](#主页结构与样例)建立四个区域，链接项目已有材料。
- **已有主页**按实际用途核对四区。例如，「任务板」里已有工作单库，就已满足 Issues 区的用途。只补尚未承载的内容，保留人工排列、子页、数据库和视图。

### 3. 衔接父页入口

在父页下建项目或受托维护总览时，按[父页条目说明](#父页上的项目条目)补齐本项目的入口。新建子页后先回读父页，复用已生成的条目。若只整理已有主页，直接进入核对。

### 4. 核对并交付

回读主页，核对项目身份、父级、四区用途和原有内容。修改过父页时，核对入口指向该主页，说明与项目材料一致。写入超时先查已保存的主页和条目，再补缺项。交付实际链接和本次结果，部分成功时指出仍缺什么。

## 父页上的项目条目

最小条目是带链接的项目名称。父页已有同类条目时，沿用其字段、排列和详略，在原布局中只补本项目的内容，保留人工备注。

例如，同级条目依次展示「项目链接、当前重点、一句简介」，就从**本项目**的 README 或已确认的讨论中提取对应内容。编号、负责人、阶段和日期等只填有依据的值。缺少可选信息就留空，父页明确要求必填且无法核实时再询问。

## 主页结构与样例

初始化时，Issues 和里程碑各用一行文字预留位置。组织执行时，`to-pm` 在这两个位置建立数据库。项目文档区链接已有材料，暂无材料时只留标题。各区的完整约定见[项目布局](../_shared/notion-project.md#主页)。

下面是「会议待办收集」项目已有一份需求讨论纪要时的主页正文。

```markdown
## Issues
这里将列出可领取的任务及其进展。

## 里程碑
这里将列出阶段目标和完成条件。

## 项目文档
- [需求讨论纪要](<已有纪要的链接>)

## 记录与归档
```
