# 论文精读与讨论

沿用团队根据 Andrej Karpathy（AK）阅读法整理的「读者冷读 → AI 解构 → 共同深挖」。第一遍由读者自己形成印象。解构帮助读者从问题推到方法，讨论帮助读者用自己的话解释机制、判断证据能支持到哪里。可以从当前卡住的地方进入。

## 执行流程

1. **判断读到哪里。** 尚无材料时，请读者给论文、链接或相关片段，并在需要时确认是否已通读。只给了全文且用意不清时，先定位材料，再简短确认进度。正在冷读且只想要路线，就指出先看哪个问题、图表或定义，把形成判断的机会留给读者。已通读并要求整体理解，进入解构；明确说“带我讨论”就直接开题。只问一个公式、实验或应用时，先解答这一点。已有笔记或上轮疑问时，从那里接上。
2. **定位所读原文。** 核对题名、版本和当前能看到的材料。PDF 的图表、扫描页和复杂公式按原页核对，数字和关键判断注明节、式、图表或附录。只拿到截图或片段时，先回答它能支撑的部分，指出再看哪一处才能解决余下的问题。
3. **解构完整论文。** 从正文逐节扫描，追到支撑主要主张的实验、证明或附录。从结论倒推所需前提，再回原文验证最容易断的一步。需要逐节线索、证据表或笔记格式时读[解构参考](references/deconstruction.md)。给读者三项成果：
   - **整体逻辑链。** 用 Problem → Insight → Methodology → Outcome 串起问题、洞见、设计和结果。解释最难推通的那一步，标明哪些是作者的动机，哪些是你的重建。
   - **关键概念降维。** 从机制必须解决的问题讲起，用直观类比或可手算的例子走一遍，把对象、动作和结果对应回原符号。核心公式用 LaTeX，说明符号，改一个条件看结果怎么变，点出类比的边界。
   - **全景摘要。** 让每条主要主张都能找到推导或观察、原文位置和适用范围。保留改变判断的负结果、局限和缺失对照。方法、实验、讨论中会改变结论的内容都要交代。多篇对比时先统一任务、样本、指标及分母、训练和测量条件。条件对不齐时分别报告观测值，把可能的机制和能区分它们的对照说清。
4. **主持讨论。** 围绕读者的目标或上轮未决点，从一处原文出发，先给你的判断和理由，再提出一个答案会改变判断的问题。用户说“继续”“不知道”或希望听讲时，由你给出下一步解释、算例或反例。读者的理由暴露出误解时，找出具体卡住的一步，用小例子讲透。读者提出异议时，回到证据更新判断，分清已解决的分歧和两种解释仍相容的部分。迁移到读者场景时，区分读者明确提供的事实和讲解时假设的流程。用新证据修订旧推测，把仍需确认的处置方式或验证条件留为未决。需要辨认误解、设计对照或准备复现时查[讨论参考](references/discussion.md)。议题充分时收束为结论、成立条件与开放问题。
5. **交付和续读。** 短问答留在对话中。完整解构及长讨论用中文写成 Markdown，保留关键英文术语。先按题名、来源和版本查找已有笔记，优先更新用户指定或已在使用的文件；首次记录默认保存到 `paper-notes/<paper-slug>.md`。局部更新相关段落，保留读者原话、批注与讨论台账。每 3–5 轮或议题转换时小结一次，标出修正的认识、未决问题和验证条件。给出可打开的笔记路径、核心判断及下一轮讨论的切口。
