# 解构参考

## 逐节扫描清单

| 章节 | 要提取什么 | 常见陷阱 |
|---|---|---|
| Abstract | 一句话问题、声称的贡献、限定条件 | 把作者声称当成已证明的结论 |
| Introduction | 问题为何重要、gap 如何定义、贡献列表 | 贡献列表与后文实验不对应 |
| Related Work | 作者设定的对手是谁、差异在哪 | 漏掉最强的对手，或把综述当背景读 |
| Method | 假设、目标函数、数据流、训练/推理流程、复杂度 | 把实现细节当核心思想，忽略未言明的假设 |
| Experiments | 数据集、baseline、指标、消融、方差、算力 | baseline 未调优、算力/数据不对齐、单种子 |
| Discussion / Limitations | 作者承认的边界与未承认的边界 | 把 limitation 当免责声明，不追问后果 |
| Appendix | 证明、超参、补充实验、失败案例 | 完全不读 |

## 论文类型与 Insight 的常见形态

| 类型 | Insight 通常在哪 | 要追问的问题 |
|---|---|---|
| 新架构 | inductive bias / 计算结构 | 这个结构编码了什么先验？换掉它性能会怎样？ |
| 新目标函数 | 优化景观 / 正则化 | 它等价于什么约束？为什么原目标不够？ |
| 新数据 / 自监督 | 监督信号从哪来 | 信号来源可靠吗？会不会引入 shortcut？ |
| 分析 / 评测 | 被忽视的维度 | 揭示了什么反直觉事实？测量本身可靠吗？ |
| 系统 / 效率 | 瓶颈定位与摊销 | 瓶颈真的是它说的那个吗？端到端收益多少？ |

## 完整解构的笔记骨架

```markdown
# <论文题名>
版本与来源：<实际阅读的版本及入口>

## 整体逻辑链
Problem → Insight → Methodology → Outcome。写出最难成立的那一步和原文依据。

## 关键概念降维
从一个例子解释机制，将例子对应回公式或算法，再改变一个条件。

## 全景结构化摘要
按主要主张组织论据。需要比较多项证据时可用下表。

| 主张 | 推导或观测 | 原文位置 | 成立条件或证据缺口 |
| --- | --- | --- | --- |

## 讨论台账
记录读者原话、已修正的理解、未决问题及下一步所需证据。
```

## 例子：从 LoRA 的一个乘法讲到证据边界

读者问“低秩更新到底能改什么”。从作者面临的问题讲起：为每个任务保留整套模型代价很高。论文假设部分任务可以通过少量方向的更新适配，在训练中冻结原权重，学习两个窄矩阵。部署时可将更新合并进原权重。这给出一种可行设计，能保留多少任务性能仍要看实验。[Hu 等，§4.1、§5、§7](https://arxiv.org/pdf/2106.09685)

按式 (3) 取缩放系数为 1，用一个二维修正演示。令 $A=(1,-1)$，$B=(1,2)^T$。输入 $x=(3,1)^T$ 时，$Ax=2$，更新项 $BAx=(2,4)^T$。换成 $x=(2,2)^T$，更新项为零。可以把 $A$ 想成读出输入差值的旋钮，$B$ 决定修正朝哪个方向走。秩为 1 时，修正的大小可以变化，方向落在 $B$ 张成的直线上。这个例子只解释表达能力。原文在 §7 改变秩并测量若干任务的性能，才为“小秩在所测任务上够用”提供经验证据。
