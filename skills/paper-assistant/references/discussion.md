# 讨论参考

## 盲区分类

| 类型 | 信号 | 处理方式 |
|---|---|---|
| 概念缺失 | 把两个不同概念混用，或把机制当定义 | 先给最小定义与一个反例，再回到原问题 |
| 因果倒置 | “因为模型有 X，所以指标高” | 指出混淆变量，要求干预或等条件对照 |
| 指标混淆 | 用 loss / accuracy / BLEU 互相推断 | 说明代理指标与目标能力的关系和脱钩条件 |
| 范围外推 | 把论文条件下的结论当普遍规律 | 列出成立条件与失效边界 |
| 术语歧义 | 同一个词在不同论文里含义不同 | 先对齐定义，再讨论 |
| 文献错位 | 把后续改进当成论文原意 | 区分原论文、后续工作与社区转述 |

## 常见误解模式库

| 表面说法 | 常见误解 | 正确框架 | 追问 |
|---|---|---|---|
| loss 降了，模型更好 | 目标函数值等于任务能力 | loss 是代理指标；分布、校准、指标错位都会让二者脱钩 | 换一个指标或分布，结论还成立吗？ |
| SOTA，所以方法有效 | 性能提升可归因于该方法 | baseline 调参、算力/数据不对齐、种子方差、benchmark 泄漏 | 同算力同数据比较过吗？方差多大？ |
| 消融掉了，所以证明因果 | 去掉模块后的下降等于该模块贡献 | 参数量、容量、训练动态同时改变，还有交互效应 | 有没有等参数量对照组？ |
| zero-shot | 没在任务上训练过 | prompt 选择、训练语料污染、评测集泄漏 | 预训练数据里有没有同分布样本？ |
| 效率提升 | latency / throughput / 显存混为一谈 | 硬件、batch、并行方式、训练 vs 推理必须分开 | 什么 batch、什么硬件、端到端吗？ |
| 有理论保证 | bound 有意义 | 假设是否成立、bound 是否 vacuous、渐近还是有限样本 | 把实际参数代入，bound 还剩多少？ |
| scaling law 可外推 | 曲线能预测未来 | 分布变化、数据枯竭、最优算力分配改变 | 外推区间外有没有机制变化？ |
| 表征/注意力与行为相关 | 相关性证明机制 | 混淆变量、干预缺失 | 有没有 causal intervention？ |

## 批判清单

| 维度 | 追问 |
|---|---|
| 问题重要性 | 解决的是真问题，还是作者自造的问题？ |
| 假设 | 最强假设是什么？放松后结论还成立吗？ |
| 可识别性 | 观测到的提升能否唯一归因于该方法？ |
| 证据充分性 | 每个 claim 是否都有实验？哪个 claim 证据最薄？ |
| baseline 公平性 | 是否同算力、同数据、同调参预算？ |
| 评测效度 | 指标是否测量了它声称的能力？有无泄漏或污染？ |
| 外部效度 | 换数据集、领域、规模还成立吗？ |
| 成本 | 训练、推理、存储、标注成本是否被计入？ |
| 可复现性 | 代码、超参、数据、随机种子是否足够？ |
| 安全与伦理 | 滥用、偏见、隐私风险是否被讨论？ |

## 场景迁移矩阵

| 维度 | 压力测试问法 |
|---|---|
| 规模 | 参数或数据放大/缩小 10 倍，结论往哪边偏？ |
| 数据 | 低资源、噪声标签、分布外、时序漂移下会怎样？ |
| 资源 | 边缘设备、低延迟、低功耗、流式输入下还成立吗？ |
| 模态/领域 | 换模态、跨语言、跨学科迁移时，哪一步最先失效？ |
| 对抗 | 恶意输入、数据投毒、提示注入下失败模式是什么？ |
| 任务结构 | 多任务、持续学习、长尾分布下需要改什么？ |
| 人机协作 | 人在回路、可解释性要求、责任归属如何变化？ |

## 问题库

**假设类**

- 这个方法依赖的最强假设是什么？如果它不成立，最先坏掉的是哪一步？
- 论文的 Insight 是一个近似还是一个恒等关系？误差如何累积？

**证据类**

- 哪个 claim 的实验证据最薄？如果算力减半，哪个结论最先消失？
- 主结果的提升相对于种子方差有多大？换三个种子还显著吗？

**替代解释**

- 除了作者的解释，还有什么机制能产生同样的结果？
- 如果把方法换成一个同样增加容量的 trivial baseline，差距还剩多少？

**边界类**

- 在什么输入上这个方法会静默失败（silent failure）？
- 论文的最优超参是否是在测试集上调的？换验证集协议会怎样？

**代价类**

- 收益是否值得额外的训练/推理/标注成本？
- 如果把部署、维护、失败重试算进去，ROI 还是正的吗？

## 从读者的说法走到可检验的问题

以 LoRA 为例，读者认为小秩能应付所有任务。先定位论文里改变秩的实验，说明哪些任务、哪些设置下小秩已经够用，再问一个会改变判断的问题。比如跨语言续训只是拟检验的新场景，若要验证是否受秩限制，可以固定训练数据与预算比较多个秩，并报告哪个结果支持或削弱该解释。把预测写成待验证的推测。只有材料里实际出现的失败才能当作反例。

## 按读者的目的选依据

- **复现。** 对照数据划分、计算预算、超参、代码和随机种子，列出公开信息及仍需确认的细节。
- **迁移或找想法。** 从主张依赖的条件出发，指出新场景改变了什么，以及能区分竞争解释的最小验证。
- **多篇对比。** 对齐任务、数据和指标定义，再看设计、对照与成本。未在同等条件下测过的差异可以提出机制假设。
