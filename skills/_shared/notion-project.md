# Notion 项目布局

供 init-notion-project、to-notion、to-pm 按需读取。以项目实际约定为先，不写死账户、页面 ID 或工种。

## 分阶段建立

`init-notion-project` 定位并建立或复用项目主页。初始化时预留 Issues 和里程碑的位置。to-notion 保存方案与分类入口；simplify 审视必要性；toPM 首次组织执行时建立两个数据库并替换占位。各入口按授权调用。

## 主页

新主页依次设置 Issues、里程碑、分类文档、记录与归档。前两区先留简短占位，建库后在原位展示。已有主页沿用人工布局及已有内容。去掉数据库前的教程、重复决策表与说明；正式项目不带实验、迁移或 Linear 来源话术。

常用文档按用途在主页分类直达正文，少量文档不建立中间目录页。研发项目可参考「方案与决策」「工程与平台」「研究与学习」，按内容增减；其他项目按实际用途选择。新增文档先检查已有类别及原记录，保持一个主要维护位置。更多资料和历史记录按需折叠，代码与实验记录引用原位置。

## Issues

基础字段：任务（title）、Issue 编号（稳定且唯一）、状态（五选项）、工种（采用项目实际分类）、里程碑（relation）。负责人、日期、优先级与依赖按实际需要加入，不增加必填门槛。依赖优先原生关系，工具不支持时在正文放真实引用。

状态固定为 Backlog、Todo、In Progress、Done、Canceled，使用 status 或工具实际支持的等价 select。第一视图按五个选项分组并展示空状态；第二按工种分组，默认聚焦未完成且未取消项，并在名称中说明筛选。卡片只显示任务、编号及必要工种或状态，更多字段按需查看。

保留已有编号，新项目默认「项目标识-连续序号」。核对已取消和归档条目避免复用；可用原生唯一编号时优先使用。既有平台编号只维持身份，不成为新项目默认。工种按项目确定，跨工种工作明确牵头与协作，避免机械分层拆解。

## Milestones

基础字段：里程碑（title，短标题表达阶段目标）、核心交付（短文本）、当前情况（基于证据的短文本）、顺序（排序用）、任务（反向关系）。日期按需添加。主表只显示前三项，不罗列关联任务链接。

页面默认展开：一句目标、简短完成标准与必要条件、所属任务视图。任务视图按本里程碑真实 relation 标识筛选，显示任务、编号、状态和工种；引用同一 Issues 数据源。完整依据仅按需要折叠或引用方案；不重复写一套执行清单或工种分工表。

近期阶段清楚表达交付，远期保留细化条件。任务统计与阶段能力结论分开；不根据完成比例推断技术通过。不为排版虚构日期、负责人或成果。

## 写入与核对

读取当前工具支持的 Markdown、schema、视图配置与权限。复用现有字段和视图，保留子页和数据库真实引用；重排页面不删除其子内容。缺少视图能力时明确说明限制，用可用真实入口交付，不伪称已配置。

核对重复调用、半途失败恢复、编号唯一和归属、任务关系与视图筛选、文档分类及正文保留。API 检查和视觉检查分别说明。现有项目的人工作业布局优先保留，仅按请求优化。
