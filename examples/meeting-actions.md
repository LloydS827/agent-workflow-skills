# 示例：会议待办收集

这是一个合成练习，改编自来源工作流的 WF01 验证场景。请在你自己指定的试用项目中运行。

## 输入

团队需要在会后集中记录待办。第一轮由会议主持人录入任务、负责人和完成条件，成员查看并更新进度。候选功能包括人工录入、AI 自动提取、日历同步与统计面板。先讨论近期成果，再确定保留范围。

将这段输入连同项目名称和目标父页，交给[上手说明](../docs/getting-started.md)中的完整流程。重大取舍由使用者决定。

## 观察点

| 环节 | 检查什么 |
| --- | --- |
| 初始化 | 项目身份与父级正确，原内容保留；此时只预留位置 |
| 方案 | 用户、操作方式、范围与完成条件明确 |
| 简化 | 每项删减有依据和代价；采纳的变化回写同一方案 |
| 任务组织 | 任务覆盖最终范围，依赖真实，编号唯一，首页与阶段引用同一任务源 |
| 再次调用 | 更新原记录，保留人工备注与已完成步骤 |
| 执行反馈 | 单项 ticket 完成时，Issue 仍按整体条件判断 |

来源工作流的一次运行保留了人工录入，移除了 AI 提取、日历同步和统计，形成 2 个里程碑、4 个 Backlog Issue。它是演示结果，数量与具体拆分不作为新运行的强制答案。

## 使用边界

本案例验证从方案到任务安排的衔接。实际功能实现、团队使用效果及各环境兼容性需另行验证。作为对比评估输入时，只提供“输入”一节，把观察点和历史结果留给评估者。
